# 数据交接规范

> 用途：把“用户给的数据够不够建模”这件事变成可检查的清单，避免写到一半才发现缺字段或单位不明。
> 原则：**数据不全不写码**。宁可先要数据，也不要用假设值把结果做出来。

## 一、必须提交的内容

| 项目 | 说明 | 缺失后果 |
|---|---|---|
| 数据文件 | CSV / XLSX / XLS / JSON / TXT / MAT 任一种 | 无法进入 G1，停止 |
| 列含义 | 每一列是什么量、什么口径 | 无法判断建模是否合理 |
| 单位 | 每列的量纲（元、吨、km、℃、%） | 结果无法写进论文 |
| 时间口径 | 年份/月份/时刻，是否为累计量 | 时序建模直接出错 |
| 缺失与异常说明 | 哪些是缺失、哪些是业务上不可能值 | 清洗策略无从谈起 |
| 归属小问 | 哪个文件服务于哪一问 | 容易张冠李戴 |

确实不需要数据的题（纯推导、纯仿真、自造参数）要在需求里明说“无需数据”，并在结果文档中写清参数来源。

## 二、给用户的数据说明模板

```markdown
# 数据说明 · <项目名>

## 文件清单
| 文件 | 服务小问 | 行数 | 说明 |
|---|---|---|---|
| data/city.csv | 第 1、2 问 | 342 | 各城市逐年指标 |

## 字段字典
| 字段 | 含义 | 单位 | 类型 | 备注 |
|---|---|---|---|---|
| year | 年份 | 年 | 整数 | 2005–2024 |
| gdp | 地区生产总值 | 万元 | 浮点 | 现价 |
| treat | 是否试点 | 0/1 | 整数 | 1=试点城市 |

## 缺失与异常
- 2013 年 gdp 缺失 4 条：按前后两年线性插值。
- pop=0 的 2 条视为录入错误，已置为缺失。

## 清洗口径
- 剔除人口小于 1 万的城市（共 3 条，理由：样本不可比）。
- 全部金额统一为万元。
```

## 三、自动检查项（`check_data.py`）

1. **可读性**：文件能否打开、编码（UTF-8/GBK）、分隔符、表头行是否识别。
2. **规模**：行列数、重复行数、唯一主键是否成立。
3. **字段**：列名清单、类型推断、每列缺失率、常量列与近常量列。
4. **数值**：最小值、最大值、分位数、是否为负、是否出现明显量纲异常（如增速超过 1000%）。
5. **时间**：日期列是否连续、是否有重复时间点、频率是否一致。
6. **对齐**：需要合并的多表，主键能否一一对应，是否存在孤儿行。

检查结果写 `work/<项目名>/数据说明.md`，末尾固定带一节“待用户确认”，列出所有需要人工判断的点（单位不明、异常值是否剔除、缺失是否插补）。

## 四、缺失与异常的处理口径

- 缺失率 < 5% 且随机：可插补，注明方法与影响。
- 缺失率 5%–20%：给出插补与不插补两版结果，报告差异。
- 缺失率 > 20%：不用该字段，或明确说明并做敏感性分析。
- 异常值：先用 IQR 或 Z-Score 识别，再按业务含义判断，不能只凭统计指标删除。
- 任何清洗动作都要在 `数据说明.md` 里留痕：删了几行、为什么、对结果影响多大。

## 五、使用与存放规则

- 用户原始数据只读；清洗结果写到 `work/<项目名>/clean/`，命名带口径，如 `city_clean_interp.csv`。
- 不在 `数据集/` 下产生任何文件；不把用户数据复制进技能目录或参考库。
- 数据涉密或未授权公开时，只在本机项目目录内使用，附录里用占位说明而不贴原始数据内容。
