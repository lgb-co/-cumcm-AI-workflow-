# 附录与结果文档规范

> 依据：国赛《论文格式规范（2026 修订稿）》第四条、第五条、第十一条（原文见 `references/official/`）。
> 两份文档分工：**附录**证明“代码完整可运行”，**结果文档**证明“结果是什么、怎么得到的”。

## 一、附录文档

结构固定为五节：

1. **支撑材料文件列表**：逐条列出代码、数据、中间结果文件的路径与用途，与提交内容一致。
2. **运行说明**：环境（Python/MATLAB 版本与关键库）、安装命令、运行命令、预计耗时。
3. **源程序**：按“总入口 → 各问脚本 → 公共函数”顺序，完整贴出全部代码，标注文件路径。
4. **数据文件说明**：每个输入数据的字段含义与单位；用户自备数据注明来源口径。
5. **结果文件清单**：生成的表格、图表文件与实际路径。

硬性要求：

- 代码必须完整、可运行；不能只给片段、不能写“代码见某某”。
- 附录代码与 `code/` 目录逐字一致，由 `build_appendix.py` 做哈希校对，不一致就报错而不是照贴。
- 不出现参赛者身份、学校、赛区信息；文件路径不带个人信息（用户名、桌面路径）。
- 附录页数不限，但要先给文件列表再贴代码，方便评审查找。

## 二、结果文档

结构固定为六节：

1. **结论摘要**：逐问一句话结论 + 关键数字（不超过一页）。
2. **数据与预处理**：用了什么数据、怎么清洗、对结果的影响。
3. **模型与算法实现**：每问对着论文口径写清实现方式、参数取值来源、以及代码位置（文件与函数）。
4. **结果与分析**：逐问结果表 + 图（规范图 + 创意主图），给出与论文数值的对照。
5. **自测与验证**：三轮自测的结论、正确性对照方式（暴力解/解析解/库实现）、多种子稳定性与敏感性结论。
6. **运行说明与限制**：环境快照、运行命令、运行时间、已知限制与未解决问题。

图件要求：结果文档里的所有图均由 Python（matplotlib）脚本生成，绘图脚本必须随附录提交；MATLAB 只提供计算，不提供交付图。

写作要求：沿用 `代码编写评价/references/报告写作风格_自然专业.md` 的规则——结论先行、证据贴判断、不用套话、不堆形容词、正文不用 emoji。数值必须来自真实运行结果。

## 三、命名与格式

```text
output/<项目名>/
├── <项目名>_附录.md
├── <项目名>_附录.docx
├── <项目名>_结果文档.md
├── <项目名>_结果文档.docx
├── code/
├── figures/
├── tables/
└── 运行说明.md
```

- 默认同时产出 Markdown 源与 DOCX 成品；DOCX 由 `build_appendix.py`、`build_results_doc.py` 生成，图以原始分辨率嵌入。
- 需要 LaTeX 时另导 `附录.tex`（用 `lstlisting` 贴代码），由用户指定后再生成。
- 支撑材料只生成**文件列表**，不打包压缩包（赛前自行按 ≤20 MB 打包）。

## 四、交付前检查

- [ ] 附录里能找到每一个提交的源程序文件，路径与提交一致。
- [ ] 附录代码哈希与 `code/` 目录一致（脚本自动校验）。
- [ ] 结果文档里的数值与 `tables/` 一致，图与 `figures/` 一致。
- [ ] 运行说明写清环境版本与命令，别人按说明能复现。
- [ ] 未跑通或未验证的部分明确写出，不掩盖。
- [ ] 全文不含身份信息与个人路径。
