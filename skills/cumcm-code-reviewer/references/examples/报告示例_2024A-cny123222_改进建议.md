## 三、实质问题（P1）

### P1-1 Q2 的答案来自硬编码，搜索入口还改了区间

| 字段 | 内容 |
|---|---|
| 标签 | 阻断级正确性风险 · 非阻断形式 |
| 位置 | `problem2_2.py` 的 `col_time`；`problem2_1.py` 的 `check_col(415, 415.5, 0.01)` 与被注释的二分搜索 |
| 现象与证据 | 论文给出首次碰撞 412.473838 s；`problem2_2.py` 直接把 412.47383777 写死，`problem2_1.py` 当前只搜 415–415.5 s，能算出论文值的二分搜索是注释状态 |
| 最小改法 | 1. 恢复二分搜索调用，把搜索区间设回论文使用的时间段。2. 让碰撞时刻由搜索函数返回，而不是手写常量。3. 把搜索区间、步长、阈值写进配置并注释来源。4. 用搜索得到的时刻驱动 `problem2_2.py` 的位置与速度计算。 |
| 验收方法 | 运行日志能看到从粗搜到二分的完整过程；输出碰撞时刻与 412.473838 s 一致（保留题目要求的位数）；改上游条件后该时刻随之变化。 |
| 工作量 | 1–2 小时 |
| 预期收益 | 论文的核心答案由代码产出，而不是人工填入；消除“答案不可复现”的风险。 |
| 参考依据 | 官方 2026 格式规范第五条；修复模式库 M12 |
