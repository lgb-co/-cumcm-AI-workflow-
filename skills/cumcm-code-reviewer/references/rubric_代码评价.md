# CUMCM 代码编写评价 Rubric（自定义，非官方）v0.3 — 8 点验证链 + 环节画像

> 用途：给"代码编写评价 Skill"提供统一的逐层核验标准。
> 依据：官方评阅总则"建议有条件时对参赛队提交的程序和结果进行验证"＋赛题各问要求＋通用评分细则；
> 代码质量维度参考科研界 reproducible code review checklist 与 PEP8 / MATLAB 风格指南；
> 环节画像与失败模式参考 LLM-MM-Agent（ACL2026）"理解—执行断层"研究结论。
> 声明：官方不直接评代码，本 Rubric 为工程化自定义标准，输出一律标注"非官方、仅供参考"。

## 使用原则（评分前必读）
1. **先冻结后评分**：把该题 8 点链检查点清单列全并固定后再开始评，不中途增删、不放宽收紧。
2. **结论必带证据**：每条结论给 文件:行/函数 + 一句"为什么"；无法定位证据的判 🔍 而非臆断。
3. **简洁充分**：宁可少而准，不堆砌；8 点里没发现问题的点写 ✅ 并给一句依据即可。
4. **泛用优先**：赛题以用户提供原文为准，现场逐问拆解；仅当命中内置 CUMCM 题库（2021–2025）时叠加题库文本/官方要点做交叉校验；非题库题照常检测，不得以“题库里没有”拒绝。

## 一、输出主链（8 点，按序逐层核验）

结论标记：✅ 通过（有证据）｜⚠️ 部分/存疑｜❌ 不通过（明确问题）｜🔍 无法判定（给"如何验证"）。
每条附：**证据**（文件/行/函数/片段）+ **说明**（依据 + 影响）。

### 链1 · 代码是否实现论文模型
- 论文/思路声称的模型逐问列出（如 Q1 PCA、Q2 0-1+多目标、Q3 转运 GA、Q4 24 周滚动联合）。
- 在代码中找对应载体（函数/类/脚本）：模型真存在，还是只写在 README/注释里。
- 要素齐全：目标函数、约束、决策变量是否都进了代码。
- 判定：缺问=⚠️/❌；模型"名不符实"（注释说 A 实现是 B）=❌。

### 链2 · 算法实现是否正确
- 算法骨架合标准流程：GA（编码→适应度→选择→交叉→变异→终止）、DP（状态/转移/边界）、仿真（事件推进/收敛判据）、优化（求解器/惩罚）。
- 目标/适应度与数学模型一致：符号、求和/连乘、正负、归一化、log/exp。
- 约束真正生效（进目标或求解器），而非只写注释。
- 数值口径落实：平稳段均值、成本加成率、对数比变换等题设口径。
- 求解器/库参数合理（PCA 全量 vs 截断、MinMax 是否只该作用于部分列）。
- 判定：算法方向错/关键算子错=❌；局部参数不当=⚠️。

### 链3 · 参数是否正确
- 题给参数：附件路径/字段、转化率、产能上限(6000)、周数(24/48)、口径参数是否用对。
- 论文/思路参数：种群、迭代、交叉/变异率、权重、阈值与代码一致。
- 魔法数：集中与否、有无来源注释（对题目附录或论文公式）。
- 单位/语义：订货量当供货量、"周"当"天"、忽略工作日/双休等。
- 判定：用错题给参数=❌/P1；魔法数无来源=⚠️/P2。

### 链4 · 数据处理是否正确
- 读取：文件/sheet/列/编码/分隔符/表头。
- 清洗：缺失/异常/打折退货/无销售/无效数据处理；不过度删有效数据。
- 数据特性：成分数据（定和/共线→CLR）、时序（季节/趋势）、小样本是否被尊重。
- 字段语义与索引对齐：换算、编号错位、行列错位。
- 判定：读错数据/字段错位=❌/P0；清洗缺失或过度=⚠️。

### 链5 · 有无隐藏错误
- 边界：range 端点、1/0-based、空数组/空切片、末行末列。
- 数值：除零、NaN/inf、空切片 std/mean、浮点比较。
- 类型/广播：隐式转换、形状不匹配、字符串 vs 数值。
- 静默失败：try/except pass、to_excel 覆盖、内置名遮蔽（all/sum/max 被赋值）。
- 复制粘贴：多份相似代码（GA 三份拷贝）改一漏一。
- 调试残留：孤立表达式、print 轰炸、写死断点/临时文件。
- 判定：确定性 bug=❌；潜在风险=⚠️；风格残留=P2。

### 链6 · 结果能否复现
- 入口：主脚本/运行顺序；README/requirements/工具箱清单。
- 随机性：固定种子；多次运行稳定或说明波动。
- 路径：不依赖本机绝对路径；附件在位、命名一致。
- 结果对应：能产出论文/思路的关键数值、图表、提交文件（命名与题模板一致）。
- 实际运行：能跑则跑并记录；不能跑则 🔍＋"复现步骤+所需依赖/数据"。
- 判定：跑不通/无法按说明复现=❌/P0；能跑但结果对不上论文=❌/P1。

### 链7 · 有无严重简化
- 与论文声称方法/规模比：论文"精确/全局最优" vs 代码"贪心/随机截断"？
- 24 周滚动→单周；402 供应商固定 50 不重选；联合优化拆顺序而忽略声称的耦合。
- 查表/固定值/近似替代应计算部分；只跑缩小版数据。
- 简化有无依据（注释说明权衡）还是静默简化。
- 判定：静默严重简化、与论文不符=❌/P0-P1；有说明的合理简化=⚠️/P2。

### 链8 · 代码与论文是否一致（总体验证）
- 综合链 1–7：模型/算法/参数/数据/结果/简化与论文或思路说明对得上。
- 论文数值/图/表都能由代码生成（输出命名对应）。
- 文档声明 vs 实际：README/注释列的文件是否真存在（注释说含 Q1A1.m 但仓库没有）。
- 判定：任一链不一致且无法解释=❌；全部一致=✅；部分存疑=⚠️。

## 二、环节画像与错误传播（8 点之后必做的小结）

按五个环节给强弱（强/中/弱/未见）与一句话依据：
1. 问题理解（读题、识别各问要什么）
2. 模型与算法（模型落地、算法正确性）
3. 代码实现（结构、参数、数据、隐藏错误）
4. 运行复现（能否跑通、可复现）
5. 结果验证（结果对得上题/论文、有敏感性/稳定性）

输出要点：
- **断层定位**：最强与最弱环节差在哪（参照"理解—执行断层"：常见"思路对、实现/验证弱"）。
- **错误传播**：早期环节的错误（链 3 参数错 / 链 4 读错数据）是否传导到链 6 结果、链 8 一致性；给出传播路径（如"Q1 把 A 当 B 读 → Q2 用量全错 → 结果整体不可信"）。
- **回溯修正**：代码/论文里是否出现对早期错误的修正（后问结果回查前问假设、做一致性校验），还是没有。

> 作用：把 8 点结论压成 3–5 行画像，指出"最该改哪里"，避免零散罗列。

## 四、问题分级 P0/P1/P2
| 级别 | 含义 | 示例 |
|---|---|---|
| P0 致命 | 不可运行 / 答非所问 / 违反题意红线 / 结果完全对不上且无法解释 / 关键文件缺失 | 读错附件；Q2 是 Q1 复制；依赖本机绝对路径 |
| P1 实质 | 实现与论文不符 / 数据口径错 / 缺某问落地 / 无种子不可复现 / 隐藏 bug / 严重静默简化 / 无验证或敏感性 | 论文写遗传算法实际暴力搜索；忽略平稳段口径 |
| P2 改进 | 命名混乱 / 缺注释 / 魔法数 / 效率低 / 文档缺失 / 复制粘贴残留 | 变量 a,b,c；2000 行单文件；三份 GA 拷贝 |

## 五、评分汇总（可选，非输出主体）
- A 与论文/赛题一致性（链1/3/4/7/8）≈ 45 分
- B 代码质量（链2/5/6 + 结构/命名/规范）≈ 40 分
- C 文档与交付（链6 运行说明 + README/依赖）≈ 15 分
- 档位：90–100 逐问落地且可复现规范；75–89 主体到位有 P1；60–74 部分落地；<60 有 P0。
> 分数仅横向参考，**输出主体是 8 点链 + 环节画像**；不给奖项位次。

## 六、与官方要点衔接
- **泛用口径**：非 CUMCM、或 CUMCM 但无内置官方要点的题，一律“按用户赛题各问要求 + 本 Rubric 通用规则”检测，并在报告注明“该题无官方要点，评分为估计”。
- 有官方要点的题：把每问"必含要素/结果口径"转成链 1/2/3/4 具体检查点（例：2022A 须给最优阻尼系数与功率 → 查代码是否输出这些量并落文件）。
- 无官方要点全文：用赛题文本各问要求 + 本 Rubric，报告注明"该题无官方要点全文，评分为估计"。
