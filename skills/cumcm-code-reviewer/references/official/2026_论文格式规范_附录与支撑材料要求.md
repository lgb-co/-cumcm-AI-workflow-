# 全国大学生数学建模竞赛论文格式规范（2026 年修订稿）· 附录与支撑材料相关条款

> 来源：全国大学生数学建模竞赛官网 mcm.edu.cn，论文格式规范（2026 年修订稿），2026-03-03 发布。
> 抓取日期：2026-09-10。原文快照存于本工作区 `训练语料/references_sources/cumcm_official_rules.html`。
> 用途：作为代码评价技能里“资格级红线”的官方依据；条款原文以官网当届文件为准。

## 与代码评价直接相关的原文条款

**第四条** 论文从第四页开始是正文内容（不要目录，不超过 30 页）；正文之后是论文附录（页数不限），附录内容必须打印并与正文装订在一起提交。

**第五条** 论文附录内容应包括支撑材料的文件列表，建模所用到的全部完整、可运行的源程序代码（含 EXCEL、SPSS 等软件的交互命令）等。如果缺少必要的源程序、程序不能运行或运行结果与论文不符，都可能会被取消评奖资格。如果确实没有用到程序，应在论文附录中明确说明“本论文没有用到程序”。

**第十一条** 支撑材料内容包括用于支撑模型、结果、结论的所有必要材料，至少应包含建模所用到的所有可运行源程序、自主查阅使用的数据资料（赛题中提供的原始数据除外）、较大篇幅中间结果的图表等。将所有支撑材料文件使用 WinRAR 软件压缩在一个文件中（后缀为 RAR 或 ZIP，大小不超过 20MB）。支撑材料的文件列表应放入论文附录；如果确实没有需要提供的支撑材料，可以不提供支撑材料文件，并在论文附录中注明“本论文没有支撑材料”。如果支撑材料文件与论文内容不相符，该论文可能会被取消评奖资格。

> 同规范还要求：论文摘要页、正文和附录中任何地方都不能有显示参赛者身份、所在学校及赛区的信息；电子版论文必须与纸质版（含附录）完全一致，且为单个文件、PDF 或 Word、不超过 20MB。

## 对代码评价的四条硬性推论

1. **附录必须能看到完整源程序**：只交结果文件、只交部分代码、只交截图或只写“代码见某某”，都不符合第五条。
2. **程序必须能运行**：不能以“作者机器上跑过”为理由通过；缺依赖、缺数据、路径写死导致跑不起来，属于资格风险。
3. **代码结果必须与论文一致**：论文里的数值、图表、表格要能由随附代码生成；对不上就要在报告里给出具体页码/表格与代码输出的差异。
4. **支撑材料必须与论文相符**：支撑材料里的程序、数据、中间结果目录要与论文正文描述一致；多套互相矛盾的版本、缺失的原始数据入口都算风险。

## 报告中如何呈现

在报告的“资格级红线检查”一节逐条给结论，并附证据（附录页/文件路径/运行输出）：

| 编号 | 检查项 | 结论（✅/⚠️/❌/🔍） | 证据 |
|---|---|---|---|
| Q1 | 附录/支撑材料是否含完整可运行源程序与文件列表 | | |
| Q2 | 代码能否在干净环境按说明运行 | | |
| Q3 | 代码结果是否与论文数值/图表一致、支撑材料与论文是否相符 | | |

任一 ❌ 或 🔍（无法判定）都要在该节置顶提示，并说明可能影响参赛资格，而不是只放在普通 P1 问题里。
