# 文档导出与工具检测（Word / PDF）

两份交付物（建模方案、数据与来源）默认以 Markdown 产出并落盘；用户需要 Word 版时，按本文件导出 `.docx`。

## 一、铁律：先检测环境，再动手

导出前必须先运行：

```
<MODELING_PY> 数学模型建立/scripts/check_docx_toolchain.py
```

检测结论分三档处理：

| 检测结果 | 处理方式 |
|---|---|
| 能写 DOCX（python-docx + Pillow + 公式渲染链路可用） | 直接运行 `scripts/export_docx.py` 导出 |
| 缺少必要包或解释器不合适 | 先尝试安装或改用 `MODELING_PY` 指定的解释器；都不可行就**停下来问用户** |
| 完全没有可用的生成工具 | 不要硬造（例如把公式写成纯文本、把 Markdown 改名成 .docx）；向用户说明缺什么并给可选方案，等用户决定 |

| 检测项 | 用途 | 缺失后果 |
|---|---|---|
| python-docx | 生成 DOCX 本体 | 无法生成 Word |
| Pillow | 量取公式与图片尺寸 | 图片尺寸失控、可能溢出页面 |
| matplotlib(mathtext) | 本地渲染公式为图片 | 只能依赖在线服务，断网即失败 |
| latex.codecogs.com | 复杂公式（如 cases 环境）在线兜底 | 复杂公式渲染不出来 |
| LibreOffice / WPS / Word | DOCX 转 PDF 再转页面图，做页面级版式校验 | 只能结构校验，必须如实告知用户并请其预览 |
| mermaid.ink / kroki.io | 思路图 Mermaid 转 PNG | 思路图只能保留 Mermaid 源码 |

## 二、导出流程

1. 运行环境检测并记录结论。
2. 检查前置条件：公式编号连续、尾注闭合、思路图已由 `scripts/render_mermaid.py` 渲染。
3. 运行 `scripts/export_docx.py --md <方案.md>`，数据文档同样导出；缺省输出为与 Markdown 同名的 .docx。
4. 有版式校验工具时：DOCX 转 PDF 再转页面图，逐页确认无溢出、无空页、图表未断裂。
5. 没有版式校验工具时：只做结构校验（段落/表格/图片数量、公式编号是否齐全、是否残留 `$$` 或 `\tag` 文本），并在交付说明中写明“版式请用办公软件预览”，不得声称做过视觉检查。
6. 交付：DOCX 放入用户指定目录（未指定时与 Markdown 同目录）。

## 三、DOCX 生成约定

- 公式：优先本地 mathtext 渲染为高清 PNG（当前环境没有可靠的 LaTeX 转 Word 原生公式路径）。用户明确要求“可编辑公式”时，说明限制并询问是否接受图片公式。
- 公式编号：用两列无边框表格排版（左列公式居中、右列 `(n)` 右对齐），保证与正文引用一致。
- 含中文的约束（如 cases 环境里的中文说明）：拆成“公式 + 项目符号列表”，避免公式内出现中日韩字符导致渲染失败或乱码。
- 表格：外框与内线用浅灰 `#D9D9D9`，表头深蓝底白字，隔行浅色底纹，行高自适应不裁剪文字。
- 标题与正文：标题微软雅黑加粗黑色，正文宋体/Times New Roman 10.5pt，A4 页边距 2.4–2.6 cm，不用页眉页脚与横向分割线。

## 四、常见故障与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| 公式本地与在线都渲染失败 | LaTeX 含中日韩字符，或用了 mathtext 不支持的宏（如 `\ge`、`\le`、`\iff`） | 归一化宏（改 `\geq`、`\leq`、`\Leftrightarrow`），把中文标注移出公式；仍失败则在交付说明标注该式未渲染 |
| DOCX 里公式是空框 | 图片被裁剪或未嵌入 | 用结构校验确认 media 数量，重新导出 |
| 图片插入位置串位 | 二次渲染时按旧文本偏移插入 | 先清理旧图片标记，再在清理后的文本上重新定位代码块 |
| 无法生成页面图 | 未安装 LibreOffice，WPS COM 未注册 | 如实说明；请用户用本机办公软件预览，或提供可用转换器路径 |

## 五、收尾归集到「论文建模」

任务结束前的最后一步：在**用户指定路径**下建立文件夹 `论文建模`，把交付物集中进去。

- 命令：`python scripts/package_deliverables.py --src "<交付目录>" --base "<用户路径>"`
- 默认结构：`<用户路径>/论文建模/<年><题>-<题目简称>/`；要求平铺时加 `--flat`；改文件夹名用 `--folder`。
- 归集内容：两份 DOCX、`图片/`（思路图 PNG）、两份 Markdown 源稿、`data/`（原始数据与清洗结果、汇总表）以及《交付清单.md》。
- 路径规则：用户给了路径就用用户路径；没给就先用工作区根目录，并在交付说明里写明实际落盘位置；不要把交付物写进 `数据集/` 等只读资料目录。
- 幂等：同名文件覆盖，不同题目的目录互不影响；重复执行不会产生副本堆积（除 data 内新增文件）。
