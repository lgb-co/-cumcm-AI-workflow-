# 阶段契约与门禁

本文件是 `cumcm-fullflow` 的执行细则：每个阶段的输入、产物、门禁、失败处理，以及最终交付核验表。

## S1 建模（技能：数学模型建立）

- **输入**：`00_题目/` 下的赛题原文与附件；题目年份题号无法确定时先问用户。
- **产物**：`01_建模方案/` 下的《建模方案（模型与公式）》《数据与来源》、`data/raw|clean`、`data/汇总数据.xlsx`、思路图。
- **门禁A · 数据确认**（仅需外部数据的题）：把《数据需求清单》与检索到的候选数据源一起给出，逐项说明口径、范围、精度是否满足，再问“是否采用”。用户否决就回到数据源选择重做。
  - 提问模板：`本题需要 <量> 共 N 项外部数据。候选来源见 <路径/链接>，其中 <项> 的口径与题目要求存在 <差异>。推荐采用 <来源>，理由是 <理由>；代价是 <代价>。是否采用？`
  - 纯建模题无外部数据需求时跳过，并在方案中写明“本题不依赖外部数据”。
- **门禁B · 模型定稿**：给出假设、符号、各问模型与公式骨架、检验计划、数据口径摘要，问“是否按此定稿”。用户改选则回 S1 受影响部分重做。
- **失败处理**：附件读不出、赛题歧义、数据缺口无法用合规来源补齐时，停下并给选项，不要带病推进。

## S2 方案评审（技能：cumcm-model-review）

- **输入**：`00_题目/` 全部题目与附件、`01_建模方案/` 的按小问脉络、用户指定的报告保存路径（`02_方案评审/`）。
- **产物**：评审报告（材料画像、逐问契合度、逐模型/算法评议、联网证据表、按优先级的修改方案、优化后的建模脉络、待核验项）。
- **循环**：把 P0/P1 问题逐条落实到 `01_建模方案/` 的修订，修订说明写入 `02_方案评审/修订说明.md`（第 n 轮新增/修改了什么、对应哪条问题）。改完再评一轮。
- **停止**：无 P0/P1，或得分不再上升，或满 3 轮。
- **注意**：评审判定的是方案设计，不要求已有实验结果；不要因为“没跑实验”而扣分，也不要因为“模型常见”而扣分。

## S3 代码实现（技能：cumcm-code-writer）

- **输入**：定稿的模型、算法、模型框架与数据；赛题原文用于对齐小问与红线。
- **环境变量**：`CUMCM_CODE_PROJECT=<运行目录>`，使产物落到 `<运行目录>/output/` 与 `<运行目录>/work/`；收尾再归集到 `03_代码/`。
- **产物**：`code/`、`figures/`、`tables/`、`results/`、附录（Markdown+DOCX）、结果文档（Markdown+DOCX）、`运行说明.md`，以及 `work/<项目名>/` 下的数据说明、环境快照、参考依据、三轮自测记录、论文口径、门禁检查。
- **硬门禁**：G0 题意与算法自洽、G1 数据齐全可用、G2 工具齐全（Python 为强制项）、G3 参考实现命中；未过即出《待补清单》，不要继续写码。
- **失败处理**：缺 Python 直接停下请用户安装；MATLAB/工具箱缺失只报告并给替代方案，不静默降级。

## S4 代码检测（技能：cumcm-code-reviewer）

- **输入**：赛题、`03_代码/` 的代码与论文口径、以及（若有）论文草稿。
- **产物**：`04_代码检测/` 下的检测报告（逐问映射、8 点检测链、运行结果、环节画像与错误传播、P0/P1/P2 清单、参考分）。
- **循环**：P0/P1 逐条修复或明确说明为何不修；`04_代码检测/修复记录.md` 记录每条问题的处理与复验结论，然后复检。
- **停止**：无 P0/P1，或修码引入的新问题超过修复收益，或满 2 轮。
- **注意**：官方不评代码，报告须写明“非官方检测、仅参考”，不给奖项位次。

## S4R 结果驱动的模型复盘与优化（技能：数学模型评价 / cumcm-model-review）

- **前置门禁（硬）**：S4 回执校验通过且检测报告判定"代码合格"（无 P0；P1 已修复复检或写明不修的理由与影响）。未合格先回 S3 → S4，**不得抢跑**。
- **位置**：S4 判定合格之后、S5 论文起草之前——结果已被独立验证，此时才有条件判断模型本身是否站得住。
- **输入**：赛题与附件、`01_建模方案/`、`03_代码/output/**` 的结果表与图件、`04_代码检测/` 的检测报告；`03_代码/work/**` 只作线索。
- **产物**：`04_代码检测/模型复盘与优化报告.md`（假设逐条核查、结构与机制缺口、参数与灵敏度、可执行优化清单与优先级、是否需要返工的结论）与回执字段 `model_change`。
- **必须独立复算**：从附件与结果表自行复算 ≥3 个关键量，写明来源与偏差。
- **循环**：`requires_rerun=true` → 回 S3 改码/重跑 → S4 重验 → S4R 复评（≤2 轮）；`false` → 记录"模型定稿（结果验证后）"，进 S5。
- **停止**：模型定稿；或两轮仍不收敛时把偏差表交用户拍板。
- **禁止**：为凑改动而改模型；改了模型却不重跑代码；把"结果看起来合理"当作模型正确的证据。

## S5 论文成文（技能：cumcm-paper-writer）

- **输入**：赛题、`01_建模方案/`、`03_代码/` 的结果文档与图表、`03_代码/work/<项目名>/论文口径.md`、`02_方案评审/` 的终稿脉络。
- **产物**：`05_论文/` 下的正文 Markdown、DOCX、PDF（版式核对用）与格式自检表。
- **前置检查**：论文里要出现的每个数值都能在结果表里找到；找不到就先补跑或补口径说明，不要先写论文。
- **禁止**：编造结果、编造文献、把未跑通的结果写成已通过。

## S6 交付核验

| 项 | 检查方式 |
|---|---|
| 阶段齐全 | `00_流程日志.md` 中 S1–S5 均有记录，无空阶段 |
| 门禁留痕 | 门禁A/B 的用户答复要点已写入日志 |
| 数字一致 | 论文正文数值 ↔ 结果表 ↔ 代码输出 三者一致 |
| 图表可追溯 | 每张图能追到绘图脚本与数据文件 |
| 附录合规 | 附录含支撑材料文件列表与全部完整可运行源码；扫描无身份信息 |
| 匿名 | 论文（摘要、正文、附录）不含参赛者姓名、学校、赛区信息 |
| 文件规格 | 电子版论文为单个 PDF/Word、≤20MB；支撑材料压缩包 ≤20MB |
| 重跑可复现 | 按《运行说明》能在干净环境重跑代码并复现结果 |

核验结果写入 `交付/交付清单.md`，同时在流程日志追加一行。

## 流程日志行格式

```text
| 2026-09-10 22:40 | S2 | 02_方案评审/评审报告_v2.md | 无 P0，剩 2 条 P1 已接受 | 用户未确认新增假设 H7 |
```

## 何时停下来问用户

- 门禁A、门禁B；
- 上游产物缺失或与本次赛题不匹配；
- 达到迭代上限仍存在 P0；
- 需要外部数据/文献但无法在规定来源内取得；
- 代码跑不通且短期无法修复；
- 发现论文数字与结果表冲突且无法判断以哪边为准。

## 修订与复评的接口约定

- 修订方（作者）在每轮修订后必须产出 `02_方案评审/修订说明_S2第n轮.md`（或代码阶段的 `04_代码检测/修复记录.md`），内含**来源表**：编号 / 来源 / 支撑结论 / 是否读到正文。
- 复评方（独立执行体）必须**独立复核来源**：DOI 能解析、链接能打开、原文确实支持该结论；发现不实来源按 critical 记录。
- 修订若涉及方程/口径变更，必须同时给出**可执行对照实验**（如 V8 的“保留/删除附加项”对照）与**失败处置**，否则复评不得通过。
- 复评通过后，来源表随运行目录归档，供代码与论文阶段引用。
