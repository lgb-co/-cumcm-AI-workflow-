# 阶段隔离与交接协议

> 目的：让每个阶段由**全新子代理**独立完成，评审与检测看不到作者的推理过程，报告不因同源锚定而失真。

## 一、铁律

1. 编排者只做四件事：建运行目录、生成密封清单、调用独立执行体、守门禁并核验回执；**不得自己产出模型、代码、论文或评审报告**。
2. 每阶段必须通过独立任务适配器创建新执行体：不继承作者对话上下文，并记录可追踪的 `session_id`/`thread_id`。适配器可按宿主平台选择独立子代理或独立任务线程，但不能把当前线程当作执行体。
3. 子代理输入只能是：赛题目录、`_handoff/<阶段>_manifest.json` 里登记的密封产物、本阶段技能的 `SKILL.md` 与 references。
4. **禁止**传入：作者对话历史、作者口头结论、未登记的手写笔记、上一阶段的自评结论（除非清单中标记为 `lead`，且只能当待验证线索）。
5. 编排者不得修改评审结论；有异议时写《异议说明》并触发复评（S2 ≤3 轮、S4 ≤2 轮、S4R ≤2 轮）。
6. 门禁 A（数据）与门禁 B（模型定稿）由用户拍板，编排者不得代答。

## 二、密封交接

- 阶段开工前：使用目标环境的明确 Python 解释器运行 `scripts/build_handoff.py --stage S2 --run-dir <运行目录>`，生成 `_handoff/<阶段>_manifest.json`，逐文件登记相对路径、字节数与 SHA-256，并标注条目角色：
  - `evidence`：可作为证据的产物（赛题、附件、上游交付文档、结果表、图件）；
  - `lead`：只作线索、不得直接采信的产物（作者的自测记录、流程日志、工作草稿）。
- 阶段收工后：独立执行体写 `_handoff/<阶段>_receipt.json`（格式见下），编排者运行
  `verify_receipt.py --manifest _handoff/<阶段>_manifest.json --receipt _handoff/<阶段>_receipt.json --base <运行目录>`
  校验：产物是否存在、哈希是否与回执一致、上游文件是否被篡改、回执字段是否齐全。校验不通过不得进入下一阶段。

## 三、回执格式

```json
{
  "protocol_version": "1.4",
  "stage": "S4",
  "status": "完成",
  "artifacts": [{"path": "04_代码检测/xxx_代码检测报告.md", "sha256": "…", "bytes": 12345}],
  "reproduction": {
    "commands": [{"command": "python tests/round2_numeric.py", "exit_code": 0}],
    "seconds": 34.6,
    "values": [{"name": "Q1 核验量", "value": 16.45, "source": "独立复跑结果"}, {"name": "Q2 核验量", "value": 7.2, "source": "附件复算"}, {"name": "Q3 核验量", "value": 0.03, "source": "结果表交叉核算"}]
  },
  "gate": {"status": "通过", "p0": 0, "open_p1": 0},
  "unresolved": []
}
```

- **S2、S4 与 S4R 必须填写 `reproduction`**：命令、耗时、独立复算值；缺此项视为未完成独立复算。S4R 还必须填写 `model_change`（见 §四表与《阶段契约与门禁》S4R 节）。
- **S1 / S2 / S2R / S4 / S4B / S4R / S5c 必须填写 `per_question_reread`**（逐问复读：`question`、`source_quotes`（原文摘录+页码）、`rounds` ≥4、`conclusion`）；其中 S1/S2/S2R/S4R 的①抄读②自解必须单开无技能预读会话。新运行回执声明 `"protocol_version": "1.4"` 并受脚本严格校验。旧协议 1.2/1.3 的历史回执仍按旧口径兼容存档，不追溯。
- **①② 必须在"无技能预读会话"完成**：独立会话、不加载任何 skill、只读 `00_题目/`，产物 `_handoff/<阶段>_preread.md`（逐问：原文摘录+页码+自解清单），用 `build_handoff.py` 封进技能会话的清单，并在回执写 `preread{artifact,sha256,session_id,no_skill:true,rounds:["抄读","自解"]}`。技能会话只做 ③对照 ④反查；若发现①②有误，回原文更正并在《问项卡》/报告标注"预读更正"。
- **协议 1.3（历史兼容）**：S1 回执须带 `self_check`；S2 回执须带 `strict_review`。旧清单/回执按旧协议存档，不追溯。
- **协议 1.4（v1.0.2 新运行）**：除 1.3 字段外，回执须声明 `"protocol_version":"1.4"`；产物用合法相对路径与完整哈希/字节数，`reproduction.commands` 每条含 `command` 与 `exit_code:0`，至少 3 条独立复算值含 `name/value/source`，`seconds` 为非负有限数；须有前置阶段完成回执和 `gate.status:"通过"`。S4/S4B/S4R 的 `gate` 还须含 `p0:0,open_p1:0`；S2 评审的 `verdict:"需返工"`、S4R 的 `requires_rerun:true` 不能作为下一阶段通过依据。完成状态不得带 P0/P1/阻塞未决项。`build_handoff.py` 会封存显式声明的 preread 文件，`verify_receipt.py` 会检查其属于 manifest 且哈希一致，前置阶段的 manifest 与产物也会重新验算；复评/复检存在时不能绕回较早回执。门禁 A/B 的用户拍板另写流程日志，不能由机器 gate 代替。
- S4 还必须在**干净副本**中复跑：把 `03_代码/output/<项目>/code` 复制到 `04_代码检测/独立复跑/`，在其中运行入口脚本与专项测试，报告中写明复跑目录与命令。
- 其它阶段 `reproduction` 可留空，但 `artifacts` 与 `unresolved` 必填。

## 四、逐阶段允许与禁止输入

| 阶段 | 允许输入（evidence） | 只作线索（lead） | 禁止输入 | 必须独立复算 |
|---|---|---|---|---|
| S1 建模 | `00_题目/**` | — | 任何既往结论 | 否 |
| S2 方案评审 | `00_题目/**`、`01_建模方案/**` | `00_流程日志.md` | 作者推理与总结 | 否（但须自行联网查证每条主张） |
| S2R 方案复评（可选，按需触发） | `00_题目/**`、`01_建模方案/**` | `00_流程日志.md` | 作者推理与总结；预读会话外的作者结论 | **是**：逐问复读 + ≥3 项独立复算 + 反驳性检查 |
| S3 写码 | `00_题目/**`、`01_建模方案/**` | — | 评审结论以外的作者结论 | 否 |
| S4 代码检测 | `00_题目/**`、`01_建模方案/**`、`03_代码/output/**` | `03_代码/work/**` | 作者的"已验证/已通过"结论 | **是**：干净副本复跑 + 关键值复算 |
| S4R 模型复盘与优化（前置：S4 判定代码合格） | `00_题目/**`、`01_建模方案/**`、`03_代码/output/**`、`04_代码检测/**` | `03_代码/work/**` | 作者自评结论与"模型已被验证"说辞；**代码未合格时不得启动本阶段** | **是**：从附件与结果表独立复算 ≥3 个关键量，并据此判断是否需要改模型 |
| S5a 起草 | `00_题目/**`、`01_建模方案/**`、`02_方案评审/**` 终稿脉络、S4/S4R 检测产物、结果表/图件/论文口径 | `03_代码/work/**` | 任何未封存的作者评论或草稿 | 否 |
| S5b 改写 | `05_论文/论文正文.md`（草稿）、风格基线、改写手册 | 风格体检报告 | 结果表与赛题（避免改写时改动事实——如需核对由校验阶段负责） | 否 |
| S5c 校验 | `05_论文/**` 上游论文和写作方《赛题要求对照表》（排除旧 S5c 自检/独立复核产物）、结果表、风格基线 | — | 改写过程记录 | **是**：格式 + 风格 + 数字集合一致性 |

## 五、失败处理

- 子代理返回"阻塞"或缺少必交产物：编排者把缺件写进《异议说明》，原阶段重派一次；再失败则停下报告，不得降级用其他技能顶替。
- 已完成但评审结论为「需返工」或代码检测不合格的回执不能通往 S3/S4R/S5；它仅可作为 S2R/S4B 等返工复评的输入。启动复评前仍须核验旧清单与报告文件/哈希，不能把失败结论伪装成通过。
- 哈希不符：说明上游产物被改动，回到改动发生的那一阶段重做，并记录原因。
- 评审结论与作者自评冲突：以评审为准进入修订；作者若要反驳，须以产物与复算数据为依据写入《异议说明》。

## 六、执行模式（按环境能力选择，不允许越权降级）

| 模式 | 触发条件 | 做法 | 标注要求 |
|---|---|---|---|
| A 隔离模式 | 独立任务适配器能传递任务正文并返回会话 ID | 按第一至五节执行：全新执行体 + 密封清单 + 回执 | 报告中注明"执行体：全新子代理/独立任务" |
| B 等待/改派 | 独立执行体无法启动、任务正文未确认送达或会话 ID 无法追踪 | 记录故障摘要，重试或改派另一个独立任务；仍失败则停下等待用户 | 不生成专业阶段产物，不写“fallback 已完成” |

- 独立任务不可用时不得由编排者代做；否则会同时破坏角色边界和评审独立性。
- 任务恢复后从未完成的阶段重新生成 manifest、重新派发，不复用未验证产物。

## 七、独立复读与复算（S2 / S4 / S4R / S5c 强制）

为保证评审真实性，以下三个阶段**必须从原始材料重建事实**，不得只读作者文档：

1. **重读赛题**：完整读一遍赛题原文（含所有表页与附录），**自行重建逐问要求清单**（问什么、必须输出什么、红线是什么），不得直接引用作者的问项卡。
2. **清点并核验附件**：逐个打开题目所列全部附件，核对文件名、工作表、行×列、字段名与单位；独立复算行数、量程、缺失/重复、单调性等结构事实。
3. **复算关键量**：至少独立复算 3 个与结论相关的数值（如恒温段均值/标准差、端面占比、特征数、稳定界），并在回执中登记。

**回执新增必填字段**（S2/S4/S5c）：

```json
"inputs_reread": {
  "problem_text": true,
  "attachments_verified": [{"path": "00_题目/附件1-烘房温湿度.xlsx", "sha256": "…", "bytes": 12345}, {"path": "00_题目/题目.txt", "sha256": "…", "bytes": 6789}],
  "question_card_rebuilt": true,
  "recomputed_values": [{"name": "附件1 记录数", "value": 241, "source": "openpyxl 独立读取"}]
}
```

`scripts/verify_receipt.py` 会校验：`problem_text=true`、`attachments_verified` 精确覆盖清单中 `00_题目/` 下全部文件（包括 `.txt`；使用完整相对路径、SHA-256 和字节数）、`question_card_rebuilt=true`、`recomputed_values` 不少于 3 条。缺项或覆盖不全即拒绝进入下一阶段。

## 八、本机环境陷阱（执行前必读）

- **裸 shell 里 PATH 上的 `python` / `python3` 是 0 字节商店别名存根**，会直接失败；裸 shell/脚本/定时任务一律显式调用绝对路径解释器：
  `工具\code_env\Scripts\python.exe`（写码与数值计算）、`工具\ocr_env\Scripts\python.exe`（OCR/PDF）或 `D:\CodexRuntime\venv\Scripts\python.exe`（VSCode 默认解释器，科学计算栈齐全）。
- **VSCode 的集成终端已配置自动激活 `D:\CodexRuntime\venv`**，在其中可直接用 `python`；这只适用于交互式终端，不要据此在脚本里写裸 `python`。
- Node 用 `C:\AIplay\nodes\node.exe`；本机另装有 VSCode 1.108.1（`code` CLI 可用于人工查看文件）。
- 详细清单见运行目录的 `环境提示.md`。

## 九、DOCX 导出约定（全阶段通用）

给作者查看/编辑的 DOCX **必须把公式转为 Word 原生公式（OMML）**：打开显示为公式、可点入编辑；
**零公式图片、零裸 LaTeX 源码**。工具：`工具\md2docx_native.py`（相对技能目录上一级，安装后即 `<skills>\工具\`；首次使用先运行 `工具\setup-md2docx.ps1` 建立带 pypandoc 的 venv）。
提交用排版版本另行生成，两者不得混用；结果文档与附录同样适用。导出件必须零 Markdown 残留（粗体星号、井号标题、表格横线、公式定界符、tag 标签、图片语法、反引号等一律不得出现在正文里），由 check_paper.py 的排版残留项机械校验。

## 十、赛题要求对照与独立复核（论文阶段强制）

1. **写作方（S5a/S5b）**：论文定稿后产出 `05_论文/赛题要求对照表.md`（模板见论文技能 references），逐条覆盖赛题原文要求，并给出论文落点与结果文件落点。
2. **独立复核（S5c，必须新建执行体）**：从**密封清单里的赛题原文**重新逐条提取要求（不得沿用写作方的清单），然后：
   - 比对两侧条目是否一一对应（缺项、重复合并、改写走样都算不合格）；
   - 对每条"满足"抽查落点真实性：打开论文与结果文件核对位置与数值（至少抽查 5 条，覆盖表/文件/精度三类）；
   - 产出 `05_论文/赛题要求对照_独立复核.md`：列出"复核条目数 / 一致 / 不一致 / 未能核验"、抽查明细与结论。
   - 其它 S5c 自检新产物统一命名为 `05_论文/_s5c_*` 或本协议约定的格式/风格/数字自检文件，不覆写 S5a/S5b 正文与写作方《赛题要求对照表》；重跑 S5c 时这些自有产物不会混入输入 manifest。
3. **S6 交付门禁**：`赛题要求对照表.md` 与 `赛题要求对照_独立复核.md` 必须同时存在；对照表中"未满足"必须为 0；独立复核中"不一致"必须为 0（否则回到写作阶段修订后重做复核）。
4. 回执（S5c）必须含：
   ```json
   "requirement_trace": {"file": "05_论文/赛题要求对照表.md", "total": 24, "satisfied": 24, "partial": 0, "missing": 0},
   "independent_trace_review": "05_论文/赛题要求对照_独立复核.md"
   ```
